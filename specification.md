# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

на разработку программного обеспечения «Image2GDRAM Converter»


## 1. Общие сведения

### 1.1. Наименование программы

Программа формирования массива данных изображения для вывода на дисплей («Image2GDRAM Converter»), версия 1.0.

### 1.2. Основания для разработки

- Документ, на основании которого ведётся разработка: договор.
- Заказчик: _________________.
- Исполнитель: ______________.

### 1.3. Среда функционирования

Компьютер под управлением ОС Windows 10 / 11 (64-разрядная).

### 1.4. Целевые платформы генерируемого кода

- Keil C51 (язык C) и ассемблер Keil A51 — архитектура Intel 8051, микроконтроллер C8051F005,C8051F410, C8051F020, C8051F121.
- Компиляторы языка C для ARM Cortex-M — микроконтроллер STM32L496Z: Keil MDK-ARM, IAR EWARM, GCC из состава STM32CubeIDE.

## 2. Назначение программы

Программа предназначена для автоматизации процесса подготовки статической графики и шрифтов. Она должна преобразовывать графические файлы и символьные наборы в байтовые массивы, совместимые со структурой памяти GDRAM следующих монохромных графических дисплеев:

1. WG240128A (контроллер RA6963 / T6963C, разрешение 240×128);
2. W0240128 (контроллер UC1608, разрешение 240×128);
3. RG12864F (контроллер NT7108, разрешение 128×64);
4. RET012864DGPP3N (OLED, контроллер SSD1305, разрешение 128×64);
5. OLED128X64-0.96 (контроллер SSD1306, разрешение 128×64);
6. HT1.3-OLED-BW / HR0161 (контроллер SH1106, разрешение 128×64).

Параметры упаковки данных для каждого дисплея приведены в приложении А.

## 3. Термины и соглашения

- Размеры везде указываются как ширина × высота (Ш×В) в пикселях. Экран 240×128 — 240 пикселей по горизонтали и 128 по вертикали; ячейка шрифта 6×8 — 6 пикселей в ширину и 8 в высоту.
- GDRAM — ОЗУ графических данных контроллера дисплея.
- Активный пиксель — точка изображения: на OLED она горит, на ЖКИ она тёмная. Без инверсии активному пикселю соответствует бит 1, фону — бит 0.
- Страница — горизонтальная полоса высотой 8 пикселей в вертикальном режиме упаковки. Страница N содержит строки 8N…8N+7.
- LSB / MSB — младший (бит 0) / старший используемый бит байта.
- Биты дополнения — биты неполного байта, которым не соответствует ни один пиксель изображения (например, при ширине, не кратной 8, в горизонтальном режиме). Биты дополнения всегда получают значение фона: 0 без инверсии, 1 с инверсией.
- Пресет — именованный набор параметров (размер и все параметры упаковки) для конкретного дисплея.
- Эталонный массив — заранее проверенный массив байтов, с которым побайтно сравнивается вывод программы при испытаниях.

## 4. Требования к функциональным характеристикам

### 4.1. Конвертер изображений

#### 4.1.1. Импорт

- Форматы файлов: BMP, PNG, JPEG, GIF.
- Размер исходного изображения — до 8192×8192 пикселей.
- Прозрачность (PNG, GIF): перед обработкой изображение накладывается на фон, выбранный пользователем (белый — по умолчанию, или чёрный). Полупрозрачные пиксели смешиваются с фоном пропорционально значению альфа-канала.
- Анимированный GIF: пользователь выбирает кадр (по умолчанию первый). Дополнительно доступен экспорт всех кадров в один двумерный массив `[число кадров][размер кадра]`.

#### 4.1.2. Порядок обработки

Изображение обрабатывается в следующем порядке, каждый шаг настраивается в интерфейсе:

1. Наложение на фон (обработка прозрачности).
2. Поворот на 0/90/180/270° и зеркальное отражение по горизонтали и/или по вертикали.
3. Приведение к целевому размеру (п. 4.1.3).
4. Перевод в оттенки серого по формуле Y = 0,299·R + 0,587·G + 0,114·B.
5. Бинаризация (п. 4.1.4).
6. Ручная правка пикселей (п. 4.1.5).
7. Инверсия и упаковка в байты (п. 4.3).

#### 4.1.3. Приведение к целевому размеру

Целевой размер задаётся пресетом, вводится вручную (п. 4.3.5) или совпадает с размером исходного изображения (режим для спрайтов и иконок). Если размер изображения не совпадает с целевым, пользователь выбирает режим:

- без масштабирования: изображение размещается согласно выравниванию, части за границами обрезаются;
- вписать с сохранением пропорций;
- растянуть без сохранения пропорций;
- заполнить с сохранением пропорций и обрезкой лишнего.

Выравнивание: по центру, по любому из углов или по середине любой стороны; дополнительно — смещение по X и Y в пикселях. Области, не покрытые изображением, заполняются фоном.

Алгоритм масштабирования выбирается пользователем: с усреднением (по умолчанию, чтобы тонкие линии не пропадали при уменьшении) или по ближайшему соседу (для пиксельной графики).

#### 4.1.4. Бинаризация

Режимы:

- пороговый: пиксель становится активным, если его яркость Y меньше порога, то есть тёмные участки исходного изображения становятся активными пикселями. Порог задаётся от 0 до 255, по умолчанию 128;
- дизеринг методом Флойда — Стейнберга;
- дизеринг методом Аткинсона;
- упорядоченный дизеринг (матрица Байера 4×4 и 8×8).

В режимах дизеринга порог задаёт уровень квантования и работает как регулятор яркости.

#### 4.1.5. Ручная правка

- Щелчок по клетке сетки переключает пиксель; при протягивании мышью левая кнопка рисует активные пиксели, правая — фон.
- Отмена и повтор действий (Ctrl+Z / Ctrl+Y).
- При изменении параметров шагов 1–5 п. 4.1.2 ручные правки сбрасываются; если правки есть, программа предварительно предупреждает об этом.

### 4.2. Генератор шрифтов

#### 4.2.1. Структура таблицы шрифта

- Массив ориентирован на прямую индексацию по коду символа: 256 ячеек с кодами от 0x00 до 0xFF в кодировке CP1251.
- Размеры ячейки: 6×8, 8×8 и 12×16 (Ш×В). Все символы моноширинные; пропорциональные шрифты (с таблицей ширин символов) в текущей версии не поддерживаются.
- Число байт на символ зависит от размера ячейки и режима упаковки (п. 4.3):

| Ячейка (Ш×В) | Вертикальная упаковка | Горизонтальная, 8 бит в байте | Горизонтальная, 6 бит в байте |
|---|---|---|---|
| 6×8 | 6 | 8 | 8 |
| 8×8 | 8 | 8 | 16 |
| 12×16 | 24 | 32 | 32 |

Общие формулы: для вертикальной упаковки — Ш × ⌈В / 8⌉, для горизонтальной — В × ⌈Ш / b⌉, где b — число бит в байте (8 или 6), ⌈ ⌉ — округление вверх. Размер массива равен 256 × (число байт на символ): например, 1536 байт для ячейки 6×8 и 6144 байта для ячейки 12×16 при вертикальной упаковке.

- Неиспользуемые символы (не входящие в выбранные диапазоны и не нарисованные вручную) заполняются значением фона: байтами 0x00 без инверсии и 0xFF с инверсией. Индексы остальных символов при этом не смещаются.

#### 4.2.2. Источники изображений символов

1. Шрифты TrueType / OpenType, установленные в Windows. Параметры: гарнитура, размер в пикселях, начертание (обычное, жирное, курсив), смещение глифа в ячейке по X и Y, режим отрисовки (со сглаживанием и последующей бинаризацией по порогу или без сглаживания). Код символа переводится в Unicode по таблице CP1251. Символы, которых нет в выбранном шрифте, остаются пустыми, их список показывается пользователю.
2. Растровый лист символов (BMP, PNG). Параметры: размер ячейки, отступ от края листа, интервал между ячейками, число символов в строке листа (по умолчанию 16), код первого символа на листе (по умолчанию 0x00). Символы читаются слева направо и сверху вниз. Бинаризация — пороговая, по п. 4.1.4.
3. Ручное рисование и правка любого символа в увеличенной сетке.
4. Импорт готового массива из файлов `.c`, `.h`, `.asm`, `.a51`, `.inc`. Программа извлекает числовые значения (шестнадцатеричные `0x..` и `..h`, десятичные, двоичные `..b`) из массива C или из последовательных директив `DB` и раскладывает их по символам согласно заданным пользователем размеру ячейки и параметрам упаковки. Если в файле несколько массивов, пользователь выбирает нужный. Если значений меньше, чем 256 × (число байт на символ), недостающие символы остаются пустыми; если больше, лишние отбрасываются; в обоих случаях выводится предупреждение.

#### 4.2.3. Диапазоны символов

Пользователь выбирает, какие коды заполнять из источников 1 и 2 п. 4.2.2. Предустановленные диапазоны:

- 0x20–0x7E — латиница, цифры, знаки препинания;
- 0xC0–0xFF, 0xA8 (Ё), 0xB8 (ё) — кириллица;
- 0x80–0xBF, кроме 0x98, — прочие символы CP1251;
- произвольный диапазон, заданный вручную.

Управляющие коды 0x00–0x1F и 0x7F, а также код 0x98 (не занят в CP1251) по умолчанию пустые; в них можно вручную нарисовать собственные символы, например пиктограммы.

#### 4.2.4. Предпросмотр строки

Поле ввода произвольной строки (по умолчанию «Привет! Hello 123»). Строка переводится в CP1251 и отображается символами из текущей таблицы в масштабе предпросмотра. Символы, отсутствующие в CP1251, отображаются пустой выделенной ячейкой.

### 4.3. Параметризация и упаковка данных

Все параметры этого раздела доступны на обеих вкладках. Выбор пресета (приложение А) устанавливает их автоматически; после ручного изменения любого параметра пресет отображается как «Пользовательский (на основе …)».

#### 4.3.1. Порядок бит в байте

- LSB first: бит 0 соответствует верхнему пикселю (вертикальный режим) или левому пикселю (горизонтальный режим).
- MSB first: старший используемый бит (бит 7, а при 6 битах в байте — бит 5) соответствует верхнему или левому пикселю.

#### 4.3.2. Направление сборки

- Горизонтальный (строчный) режим: байт содержит соседние пиксели одной строки; байты идут слева направо, строки — сверху вниз. Необходим для RA6963 / T6963C.
- Вертикальный (страничный) режим: байт содержит 8 пикселей одного столбца в пределах страницы. Необходим для SSD1306, SH1106, UC1608.

#### 4.3.3. Число бит в байте (только горизонтальный режим)

- 8 бит — по умолчанию.
- 6 бит — для T6963C в режиме шрифта FS = 6×8: используются биты 5…0, биты 7 и 6 являются битами дополнения. Строка из 240 пикселей в этом режиме занимает 40 байт вместо 30.

#### 4.3.4. Порядок обхода (только вертикальный режим, высота больше 8)

- По страницам (по умолчанию): сначала все столбцы страницы 0 слева направо, затем все столбцы страницы 1 и т. д. Совпадает с организацией GDRAM контроллеров SSD1306, SH1106, UC1608.
- По столбцам: для каждого столбца слева направо подряд идут байты всех его страниц сверху вниз.

Пример для символа 12×16. По страницам: байты 0–11 содержат строки 0–7 столбцов 0–11, байты 12–23 — строки 8–15. По столбцам: байты 0 и 1 содержат столбец 0 (строки 0–7 и 8–15), байты 2 и 3 — столбец 1 и т. д.

#### 4.3.5. Размер

- Пресеты под целевые дисплеи (240×128, 128×64) — приложение А.
- Произвольный размер, вводимый с клавиатуры: ширина и высота от 1 до 1024 пикселей.
- Размер по исходному изображению (для спрайтов и иконок) — только в конвертере изображений.

#### 4.3.6. Размеры, не кратные 8

Допускаются. Изображение прижимается к левому верхнему углу; незаполненные биты последней страницы (вертикальный режим) или последнего байта строки (горизонтальный режим) становятся битами дополнения (раздел 3). Фактические ширина и высота записываются в выходной файл (п. 4.4.3, 4.4.7).

#### 4.3.7. Инверсия цвета

Переключатель «Инвертировать»: без инверсии активный пиксель кодируется битом 1, фон — битом 0; с инверсией наоборот. Инверсия распространяется на биты дополнения и на пустые символы шрифта.

### 4.4. Формат выходных данных и совместимость

#### 4.4.1. Способы вывода

- Окно со сгенерированным текстом, обновляемое при каждом изменении параметров.
- Копирование в буфер обмена.
- Сохранение в файлы:
  - для языка C (C51 и STM32) — пара файлов `.c` и `.h`;
  - для ассемблера — файл `.a51` или `.asm` (расширение выбирает пользователь);
  - двоичный файл `.bin` — только байты массива, без заголовков.
- Перед перезаписью существующего файла запрашивается подтверждение.

#### 4.4.2. Имя массива

Задаётся пользователем. По умолчанию формируется из имени исходного файла (или гарнитуры) и размера, например `logo_128x64`, `font_6x8`. Программа проверяет, что имя:

- состоит только из латинских букв, цифр и символа `_` и не начинается с цифры;
- имеет длину не более 31 символа;
- не совпадает с ключевыми словами C и Keil C51 (`code`, `data`, `idata`, `xdata`, `pdata`, `bit`, `sbit`, `sfr` и т. д.) и с зарезервированными именами A51 (имена регистров, мнемоники команд, директивы).

Имена макросов в `.h` образуются из имени массива в верхнем регистре.

#### 4.4.3. Заголовок-комментарий

Каждый выходной текстовый файл начинается с комментария, в котором указаны:

- название и версия программы;
- дата и время генерации (отключаемо, чтобы повторная генерация давала идентичный файл);
- исходный файл или шрифт (гарнитура, размер);
- пресет дисплея;
- ширина и высота изображения или ячейки шрифта;
- направление сборки, порядок бит, число бит в байте, порядок обхода, инверсия;
- размер массива в байтах.

#### 4.4.4. Оформление данных

- Число байт в строке — от 1 до 16 (для изображений по умолчанию 16). Для шрифтов каждый символ начинается с новой строки; если байт на символ больше 16, символ переносится на несколько строк поровну.
- Формат чисел в C — только шестнадцатеричный (`0x0F`): двоичные литералы `0b…` не входят в стандарты C89/C99 и не поддерживаются Keil C51.
- Формат чисел в ассемблере — `0FFh` (по умолчанию) или двоичный `11111111b`. Шестнадцатеричное число, начинающееся с буквы, записывается с ведущим нулём.
- Для шрифтов каждый символ сопровождается комментарием с кодом и изображением символа: `/* 0xC0 'А' */` в C, `; 0C0h 'А'` в ассемблере. Для управляющих и непечатаемых кодов выводится только код.
- В C используются только блочные комментарии `/* */`: символ `\` в конце строчного комментария `//` склеивает его со следующей строкой и «съедает» строку данных.

#### 4.4.5. Вывод для Keil C51 (C8051Fxxx)

- Язык C: массив размещается в памяти программ с помощью спецификатора `code`; тип элементов — `unsigned char`.
- Ассемблер Keil A51: данные описываются директивой `DB`. Два варианта вывода:
  - самостоятельный модуль — с объявлением сегмента (`SEGMENT CODE`, `RSEG`), директивой `PUBLIC` для доступа к массиву из C и завершающей директивой `END`;
  - фрагмент для подключения через `$INCLUDE` — только метка и строки `DB`, без `END`.

#### 4.4.6. Вывод для STM32L496Z

- Массив размещается во Flash-памяти с помощью спецификатора `const`.
- Тип элементов — `uint8_t` из `<stdint.h>` (по умолчанию) или `unsigned char`.
- Спецификатор `static` не используется: массив определяется в `.c` и объявляется в `.h` как `extern`.
- Код компилируется без ошибок и предупреждений в Keil MDK-ARM (ARM Compiler 5 и 6), IAR EWARM и GCC из состава STM32CubeIDE.

#### 4.4.7. Заголовочный файл

Файл `.h` содержит защиту от повторного включения, макросы `#define` для ширины, высоты и размера массива (для шрифтов — ширины и высоты ячейки и числа байт на символ) и объявление массива с `extern`. Примеры приведены в приложении В.

#### 4.4.8. Кодировка и переводы строк

- Кодировка выходных файлов — CP1251 (по умолчанию) или UTF-8 без BOM.
- Переводы строк — CRLF.

### 4.5. Сохранение настроек

- Последние использованные параметры сохраняются автоматически и восстанавливаются при следующем запуске.
- Пользователь может сохранять, переименовывать и удалять собственные пресеты.
- Файл проекта (`.iiu`, формат JSON в кодировке UTF-8) хранит путь к исходному файлу, все параметры обработки и упаковки, ручные правки пикселей, а для шрифтов — изображения всех 256 символов.
- Настройки хранятся в файле `settings.json` рядом с исполняемым файлом; если папка недоступна для записи — в `%APPDATA%\ImageIU`.

### 4.6. Перспектива развития

- Программа состоит из независимых модулей: загрузка изображения → обработка (растр RGBA, 8 бит на канал) → упаковка → генерация кода. Добавление нового режима упаковки или формата вывода не должно требовать изменений в остальных модулях.
- Архитектура программы должна закладывать возможность расширения до цветных режимов (RGB565 для STM32) с выбором порядка байтов в 16-битном слове: старший байт первым (big-endian — как правило, для передачи в контроллер дисплея по SPI или параллельной шине) или младший первым (little-endian — порядок хранения `uint16_t` в памяти Cortex-M).
- В текущей версии для монохрома неиспользуемые биты/байты цвета должны игнорироваться.

## 5. Требования к интерфейсу (GUI)

### 5.1. Общие требования

- Две отдельные вкладки: «Конвертер картинок» и «Генератор шрифтов».
- Язык интерфейса — русский. Строки интерфейса хранятся отдельно от кода, чтобы другой язык можно было добавить без изменения программы.
- Корректное отображение при масштабе Windows от 100 до 200 %; минимальный размер окна — 1024×680.
- Время обновления предпросмотра и сгенерированного кода после изменения любого параметра — не более 200 мс для изображений до 240×128 и таблиц шрифтов, не более 1 с для изображений 1024×1024.

### 5.2. Интерактивная сетка (Grid Preview)

- Пиксели отображаются клетками; масштаб — от 1:1 до 32:1 и режим «по размеру окна».
- Линии сетки включаются и выключаются; границы байтов и страниц (каждые 8 пикселей по направлению упаковки, при 6 битах в байте — каждые 6) выделяются более толстыми линиями.
- При наведении на клетку отображаются: координаты X и Y, порядковый номер байта в массиве (десятичный и шестнадцатеричный), номер бита, значение байта (шестнадцатеричное и двоичное). Соответствующий байт подсвечивается в окне кода.
- Цветовая схема: «ЖКИ» (тёмные пиксели на светлом фоне) или «OLED» (светлые пиксели на тёмном фоне); устанавливается пресетом и может быть изменена вручную.
- Изменения режима упаковки, инверсии и порога яркости сразу видны в сетке.

### 5.3. Вкладка «Конвертер картинок»

- Исходное изображение и результат отображаются рядом.
- Порог задаётся ползунком и полем ввода (0–255).
- Элементы управления всеми параметрами п. 4.1 и 4.3.

### 5.4. Вкладка «Генератор шрифтов»

- Обзорная таблица всех 256 символов (16×16) с подписями кодов; пустые ячейки визуально отличаются от заполненных.
- Редактор выбранного символа в увеличенной сетке: переключение пикселей, очистка, инверсия символа, сдвиг на 1 пиксель в четырёх направлениях, копирование и вставка символа.
- Параметры источника (п. 4.2.2) и диапазонов символов (п. 4.2.3).
- Поле предпросмотра строки (п. 4.2.4).

## 6. Требования к надёжности

- Повреждённые, неподдерживаемые или слишком большие файлы не приводят к аварийному завершению программы; выводится сообщение с причиной ошибки.
- Недопустимые значения в полях ввода (размеры, имя массива, коды символов) сразу подсвечиваются, генерация с ними невозможна.
- Программа не изменяет исходные файлы изображений и шрифтов.
- При закрытии программы с не сохранёнными изменениями проекта выводится запрос на сохранение.
- Результат генерации детерминирован: при одинаковых входных данных и параметрах выходные массивы совпадают побайтно.

## 11. Порядок контроля и приёмки

Испытания проводятся по программе и методике испытаний, согласованной с заказчиком, и включают:

1. Сравнение с эталонами. Для каждого пресета из приложения А и для каждой допустимой комбинации параметров упаковки (порядок бит, направление сборки, число бит в байте, порядок обхода, инверсия) выходные массивы для тестовых изображений (приложение Б) и для шрифтов всех трёх размеров побайтно сравниваются с эталонными. Эталонные массивы формируются независимо от проверяемой программы (вручную или сторонним инструментом) и согласуются с заказчиком.
2. Компиляция. Сгенерированный код компилируется без ошибок и предупреждений:
   - вывод на C для C51 — в Keil C51;
   - вывод на ассемблере — в Keil A51, в обоих вариантах (самостоятельный модуль и фрагмент для `$INCLUDE`);
   - вывод для STM32 — в Keil MDK-ARM, IAR EWARM и STM32CubeIDE.
3. Проверка на дисплеях. Тестовое изображение «Таблица настройки» и строка «Привет! Hello 123», набранная шрифтами всех трёх размеров, выводятся на физические дисплеи из раздела 2. Проверка на SSD1306 и WG240128A обязательна. Если какого-либо из остальных дисплеев нет в наличии, он проверяется только сравнением с эталоном, что фиксируется в протоколе испытаний.
4. Критерий приёмки: изображение на каждом проверяемом дисплее попиксельно совпадает с предпросмотром в программе, все сравнения по п. 1 и все компиляции по п. 2 выполнены успешно.

Тестовый код(Тестовая прошивка) для вывода на дисплеи предоставляется заказчиком. Её исходный файл со строкой «Привет! Hello 123» должен быть сохранён в кодировке CP1251, иначе коды символов в строке не совпадут с индексами таблицы шрифта.

6. Закрашенный и пустой прямоугольники 16×16 — проверяют инверсию.
