# Форматы выходных данных

Тексты ниже — сокращённый вывод Image2GDRAM Converter 1.0. Дата в примерах выключена, чтобы текст не зависел от времени. Если флажок «Дата в заголовке» включён, второй строкой комментария идёт `Дата: yyyy-MM-dd HH:mm:ss`.

Байты данных взяты из упаковки тестовых изображений `testdata/test_pattern_240x128.png` и `testdata/test_pattern_128x64.png`. Они совпадают с эталонами `testdata/reference/` (тест `ReferenceFileTests`). Имя массива в примерах короче автоматического, на байты оно не влияет. Многоточие заменяет середину массива.

Кодировка файлов по умолчанию — CP1251, перевод строки CRLF, метки BOM нет. В C только комментарии `/* */` и числа `0x` с заглавными шестнадцатеричными цифрами.

Общие правила, одинаковые для всех пресетов:

- пара C — это `<имя>.c` и `<имя>.h`, файл `.c` подключает свой `.h`;
- модуль A51 — метка в верхнем регистре, сегмент `?CO?<ИМЯ>`, строки `DB` без завершающей запятой, в конце `END`;
- фрагмент `$INCLUDE` — тот же заголовок-комментарий, метка и `DB`, без `PUBLIC`, сегмента и `END`;
- BIN — те же байты без текста. В окне программы они показаны дампом `XXXXXXXX  XX XX ...`.

## WG240128A (RA6963 / T6963C)

Горизонтальное, MSB first, 8 бит в байте, без инверсии. Размер 240x128, 3840 байт. Эталон: `testdata/reference/test_pattern_240x128/h_msb_8.bin`.

`screen_240x128.h`:

```c
/*
 * Image2GDRAM Converter 1.0
 * Источник: test_pattern_240x128.png; пресет: WG240128A (RA6963 / T6963C)
 * Размер: 240x128 (ШxВ); упаковка: горизонтальная, MSB first, 8 бит в байте, инверсия: нет
 * Размер массива: 3840 байт
 */

#ifndef SCREEN_240X128_H
#define SCREEN_240X128_H

#define SCREEN_240X128_WIDTH   240
#define SCREEN_240X128_HEIGHT  128
#define SCREEN_240X128_SIZE    3840

extern unsigned char code screen_240x128[SCREEN_240X128_SIZE];

#endif
```

Начало `screen_240x128.c` для Keil C51. Первая строка изображения — рамка, поэтому первые байты равны 0xFF. В строке 30 байт, на экране их 16:

```c
#include "screen_240x128.h"

unsigned char code screen_240x128[SCREEN_240X128_SIZE] = {
    0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF,
    /* ... ещё 14 байт этой строки и остальные строки ... */
};
```

Для STM32 тот же комментарий и те же байты, а объявление другое: в `.h` есть `#include <stdint.h>` и `extern const uint8_t screen_240x128[SCREEN_240X128_SIZE];`, в `.c` — `const uint8_t` без `static`. Вариант `unsigned char` строку `<stdint.h>` не вставляет.

Если для шрифта T6963C вручную выбраны 6 бит в байте, в строке упаковки появляется `6 бит в байте`, а строка экрана занимает 40 байт.

## W0240128 (UC1608)

Вертикальное, LSB first, по страницам, без инверсии. Размер 240x128, 3840 байт (240 столбцов на 16 страниц). Эталон: `testdata/reference/test_pattern_240x128/v_lsb_pages.bin`.

```c
/*
 * Image2GDRAM Converter 1.0
 * Источник: test_pattern_240x128.png; пресет: W0240128 (UC1608)
 * Размер: 240x128 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 3840 байт
 */
```

Первые 16 байт — столбцы 0-15 страницы 0. Столбец 0 — левая рамка, все 8 бит активны (0xFF). Дальше верхняя рамка даёт бит 0:

```c
    0xFF, 0x01, 0x01, 0xF9, 0xF9, 0xF9, 0xF9, 0xF9, 0xFF, 0xF9, 0xF9, 0x01, 0x01, 0x01, 0x01, 0x01,
```

Параметры UC1608 ждут подтверждения на модуле. Если в контроллере включён MSF, порядок бит меняется на MSB first и первый байт рамки станет другим.

## RG12864F (NT7108)

Вертикальное, LSB first, по страницам, без инверсии, схема ЖКИ. Размер 128x64, 1024 байта. Эталон: `testdata/reference/test_pattern_128x64/v_lsb_pages.bin`.

```c
/*
 * Image2GDRAM Converter 1.0
 * Источник: test_pattern_128x64.png; пресет: RG12864F (NT7108 (совместим с KS0108))
 * Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 1024 байта
 */
```

Начало массива:

```c
    0xFF, 0x01, 0x01, 0xF9, 0xF9, 0xF9, 0xF9, 0xF9, 0xFF, 0xF9, 0xF9, 0x01, 0x01, 0x01, 0x01, 0x01,
```

Драйвер делит каждую страницу пополам: байты 0-63 столбца — кристалл CS1, байты 64-127 — CS2. В файле половины не разделены.

Макросы `.h`:

```c
#define SCREEN_128X64_WIDTH   128
#define SCREEN_128X64_HEIGHT  64
#define SCREEN_128X64_SIZE    1024
```

## RET012864DGPP3N (SSD1305)

Та же упаковка и те же 1024 байта, что у RG12864F для того же изображения. Меняются имя пресета, контроллер и то, что схема OLED. Смещение столбцов ОЗУ 132 точки в массив не входит.

```c
 * Источник: test_pattern_128x64.png; пресет: RET012864DGPP3N (SSD1305)
 * Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 1024 байта
```

Первая строка данных совпадает с примером RG12864F.

## OLED128X64-0.96 (SSD1306)

Та же упаковка и те же байты изображения 128x64. Это пресет с обязательной проверкой на модуле.

```c
/*
 * Image2GDRAM Converter 1.0
 * Источник: test_pattern_128x64.png; пресет: OLED128X64-0.96 (SSD1306)
 * Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 1024 байта
 */

#include "screen_128x64.h"

const uint8_t screen_128x64[SCREEN_128X64_SIZE] = {
    0xFF, 0x01, 0x01, 0xF9, 0xF9, 0xF9, 0xF9, 0xF9, 0xFF, 0xF9, 0xF9, 0x01, 0x01, 0x01, 0x01, 0x01,
    /* ... */
};
```

Файл `.h` для STM32:

```c
/*
 * Image2GDRAM Converter 1.0
 * Источник: test_pattern_128x64.png; пресет: OLED128X64-0.96 (SSD1306)
 * Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 1024 байта
 */

#ifndef SCREEN_128X64_H
#define SCREEN_128X64_H

#include <stdint.h>

#define SCREEN_128X64_WIDTH   128
#define SCREEN_128X64_HEIGHT  64
#define SCREEN_128X64_SIZE    1024

extern const uint8_t screen_128x64[SCREEN_128X64_SIZE];

#endif
```

Тот же массив модулем A51 (числа `0FFh`, дата выключена, показаны только первые строки):

```asm
; Image2GDRAM Converter 1.0
; Источник: test_pattern_128x64.png; пресет: OLED128X64-0.96 (SSD1306)
; Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
; Размер массива: 1024 байта

                PUBLIC  SCREEN_128X64

?CO?SCREEN_128X64 SEGMENT CODE
                RSEG    ?CO?SCREEN_128X64

SCREEN_128X64:
                DB      0FFh, 001h, 001h, 0F9h, 0F9h, 0F9h, 0F9h, 0F9h, 0FFh, 0F9h, 0F9h, 001h, 001h, 001h, 001h, 001h
                ; ...
                END
```

Фрагмент для `$INCLUDE` начинается с тех же строк комментария, затем сразу метка `SCREEN_128X64:` и строки `DB`. Директив `PUBLIC`, `SEGMENT`, `RSEG` и `END` нет.

BIN — 1024 байта, первый из них `FF`, второй `01`.

## HT1.3-OLED-BW / HR0161 (SH1106)

Упаковка и байты изображения совпадают с SSD1306. В комментарии другое имя пресета:

```c
 * Источник: test_pattern_128x64.png; пресет: HT1.3-OLED-BW / HR0161 (SH1106)
 * Размер: 128x64 (ШxВ); упаковка: вертикальная, LSB first, по страницам, инверсия: нет
 * Размер массива: 1024 байта
```

Сдвиг видимой области на 2 столбца в эти 1024 байта не записывается. Его делает драйвер.

## Шрифт

Шрифт для тех же контроллеров упаковывается так же, но массив двумерный: 256 символов, символ `c` занимает байты `c * N ... c * N + N - 1`. Для вертикальной ячейки 6x8 N = 6, весь массив — 1536 байт. Эталон пустого и нарисованного шрифта листа — `testdata/reference/font_6x8/`.

Сокращённый заголовок C51, дата выключена, пресет SSD1306, ячейка 6x8, вертикальная упаковка без инверсии:

```c
/*
 * Image2GDRAM Converter 1.0
 * Шрифт: лист font_sheet_6x8.png; ячейка 6x8 (ШxВ)
 * Упаковка: вертикальная, LSB first, инверсия: нет; пресет: OLED128X64-0.96 (SSD1306)
 * Размер: 256 символов x 6 байт = 1536 байт
 */

#define FONT_6X8_CHAR_WIDTH      6
#define FONT_6X8_CHAR_HEIGHT     8
#define FONT_6X8_BYTES_PER_CHAR  6

extern unsigned char code font_6x8[256][FONT_6X8_BYTES_PER_CHAR];
```

Высота ячейки 8, поэтому слова «по страницам» в строке упаковки нет: при высоте не больше 8 оба обхода совпадают. У ячейки 12x16 высота 16, и слова «по страницам» или «по столбцам» в комментарии есть. 24 байта символа пишутся двумя строками по 12.

В прошивке символ берётся так:

```c
unsigned char code *glyph = font_6x8[(unsigned char)c];
```

Строка на дисплее должна быть в том же CP1251, что и таблица. Иначе «Привет» не попадёт в ячейки 0xCF, 0xF0, 0xE8, 0xE2, 0xE5, 0xF2.
