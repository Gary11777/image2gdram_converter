# Программа и методика испытаний. Image2GDRAM Converter 1.0

Документ задаёт состав и порядок приёмки по разделу 11 технического задания. Испытания на физических дисплеях и компиляцию в Keil, IAR и STM32CubeIDE выполняет заказчик: этих сред и модулей на машине разработки нет. Сравнение с эталонами выполняется автоматическим тестом и может быть повторено заказчиком.

Эталонные массивы и пресеты UC1608, NT7108 и SSD1305 подготовлены исполнителем и ждут согласования (вопросы Q-01 и Q-08 в `docs/decisions.md`). До согласования они действуют как эталон по умолчанию.

## 1. Объект

Программа Image2GDRAM Converter версии 1.0, опубликованный файл `publish/image2gdram_converter.exe` (Windows x64, в комплекте с зависимостями, без установки .NET).

Входы:

| Файл | Назначение |
|---|---|
| `testdata/test_pattern_240x128.png` | Таблица настройки 240x128, приложение Б |
| `testdata/test_pattern_128x64.png` | Таблица настройки 128x64, приложение Б |
| `testdata/test_sprite_13x11.png` | Фигура 13x11, размеры не кратны 8 |
| `testdata/font_sheet_6x8.png` | Лист шрифта 6x8, 16 символов в строке |
| `testdata/font_sheet_8x8.png` | Лист шрифта 8x8 |
| `testdata/font_sheet_12x16.png` | Лист шрифта 12x16 |
| `testdata/reference/` | Эталонные `.bin` и `.c`, описание в `index.md` |

Раскладка тестовых изображений — решение N-40, листов и эталонов — N-60. Рисунки листов построены встроенным растром 5x7, не системным шрифтом.

## 2. Состав испытаний

1. Сравнение с эталонами. Для каждого размера из пресетов приложения А (240x128 и 128x64), для спрайта 13x11 и для шрифтов 6x8, 8x8 и 12x16 — все 16 допустимых комбинаций упаковки. Горизонтальный режим: порядок бит, 8 или 6 бит в байте, инверсия. Вертикальный: порядок бит, обход по страницам или по столбцам, инверсия.
2. Компиляция сгенерированного текста без ошибок и предупреждений: C51 в Keil C51; оба варианта A51 в Keil A51; STM32 в Keil MDK-ARM (ARM Compiler 5 и 6), IAR EWARM и STM32CubeIDE (GCC).
3. Вывод на дисплеи. Тестовое изображение «Таблица настройки» и строка «Привет! Hello 123» шрифтами 6x8, 8x8 и 12x16. Проверка на SSD1306 и WG240128A обязательна. Остальные модули, если их нет, проверяются только сравнением с эталоном, и это отмечается в протоколе.
4. Запуск опубликованной программы под обычным пользователем, в том числе без установленного .NET и без сети. Файл `settings.json` создаётся рядом с exe либо, если папка недоступна для записи, в `%APPDATA%\ImageIU`.

Критерий приёмки: на каждом проверенном дисплее изображение попиксельно совпадает с предпросмотром, все сравнения п. 1 и все компиляции п. 2 успешны. Для модуля, отмеченного «только эталон», критерий п. 1 заменяет проверку на стекле.

Тестовую прошивку предоставляет заказчик. Её исходный файл со строкой «Привет! Hello 123» должен быть сохранён в CP1251.

## 3. Порядок

### 3.1. Сборка и автоматические проверки

На машине с .NET SDK 8:

```powershell
.\build.ps1
```

Ожидается сборка Release без ошибок и предупреждений и зелёные тесты. Побайтное сравнение с файлами эталонов — тест `ReferenceFileTests.Images_and_font_sheets_match_reference_bins_and_c_files`. Он читает PNG через WIC, упаковывает ядром и сравнивает с `.bin`. Файл `.c` рядом разбирается как массив C и должен содержать те же байты.

Повторить генерацию эталонов, если менялась независимая реализация или раскладка листов:

```powershell
dotnet run --project tools/TestAssetsGenerator -c Release
dotnet test -c Release --filter FullyQualifiedName~ReferenceFileTests
```

Эталоны после повторной генерации снова согласуются с заказчиком.

Дополнительно, уже выполнено на машине разработки и может быть повторено:

- время обновления предпросмотра и кода (`dotnet run -c Release --project tools/UiProbe -- perf`): для 240x128 не больше 200 мс, для 1024x1024 не больше 1 с, для таблиц шрифтов не больше 200 мс. Замер 2026-10-07: максимум 85 мс, 160 мс и 83 мс соответственно;
- окно 1024x680 при масштабе 100, 125, 150, 175 и 200 процентов (`tools/UiProbe dpi`): обрезанных элементов нет. Смена масштаба Windows на физическом мониторе остаётся пунктом этой методики;
- дымовая компиляция `tools/compile-check.ps1`: если есть gcc, clang или arm-none-eabi-gcc, скрипт компилирует образец STM32 с `-std=c99 -Wall -Wextra -pedantic -Werror` и образец C51 с `-Dcode=`. Если компилятора нет, скрипт сообщает об этом и завершается с кодом 0. Это не заменяет Keil, IAR и STM32CubeIDE.

### 3.2. Публикация и запуск

```powershell
.\publish.ps1
```

Запустить `publish\image2gdram_converter.exe` пользователем без прав администратора. Убедиться, что окно открылось, обе вкладки переключаются, после закрытия рядом с exe появился `settings.json`. Повторить на Windows 10 и Windows 11, если приёмка идёт на обеих системах. Сеть для запуска не требуется.

### 3.3. Компиляция у заказчика

Для каждого нужного пресета сохранить из программы:

- C для C51 и оба варианта A51 — если цель 8051;
- C для STM32 (`uint8_t` и, отдельно по желанию, `unsigned char`) — если цель STM32L496ZG.

Собрать без ошибок и предупреждений в средах раздела 2. В протокол записать версию компилятора.

### 3.4. Дисплеи

Для каждого имеющегося модуля:

1. Выбрать пресет. Параметры и оговорки — раздел 7 `docs/user_guide.md` (смещение SH1106 на 2 столбца делает драйвер, две половины NT7108 тоже делает драйвер, для шрифта T6963C 6x8 вручную включаются 6 бит в байте).
2. Открыть таблицу настройки нужного размера. Сравнить стекло с сеткой: рамка по краю, маркеры по углам, диагональ без зигзага внутри байта, шахматное поле, оба прямоугольника, надпись размера.
3. Загрузить шрифт трёх размеров и вывести строку «Привет! Hello 123». Индекс символа в прошивке — `font[(unsigned char)c]`.
4. Если модуль есть только как эталон, отметить это в протоколе и не ставить отметку «совпало на стекле».

SSD1306 и WG240128A без отметки «проверен на модуле» приёмку не закрывают.
