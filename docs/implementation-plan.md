### Уточнения привязки работ к этапам

- **Сверка пресетов с datasheet** (приложение А ТЗ, примечание 1: «на этапе 1») выполняется на этапе 1 по общедоступным сведениям о контроллерах. Окончательное подтверждение пресетов UC1608, NT7108 и SSD1305 остаётся за заказчиком (решение D-01 в [`decisions.md`](decisions.md)).
- **Генератор тестовых изображений** приложения Б (`tools/TestAssetsGenerator`) создаётся на этапе 2, а не на этапе 9: изображения нужны тестам конвейера (повороты и отражения проверяются по маркерам), а приложение Б ТЗ указывает «на этапе 2». На этапе 9 к нему добавляются листы шрифтов и эталонные массивы (решение N-01).
- **Независимая эталонная реализация упаковки** (`tests/Image2Gdram.Reference`) создаётся на этапе 1 вместе с ядром упаковки; на этапе 9 по ней формируются файлы эталонов.

## Разбивка этапа 1 (следующий этап)

Первый шаг — структура решения. Код продукта на этапе 0 не создавался.

1. Перенести заготовку WPF из корня в `src/image2gdram_converter/` командой `git mv` (`App.xaml`, `App.xaml.cs`, `AssemblyInfo.cs`, `MainWindow.xaml`, `MainWindow.xaml.cs`, `image2gdram_converter.csproj`). Имя проекта, пространство имён `image2gdram_converter` и пакеты (`SixLabors.ImageSharp` 4.1.2, `CommunityToolkit.Mvvm` 8.4.2) сохранить. ImageSharp переносится в Core на этапе 2 вместе с декодером ([`architecture.md`](architecture.md), раздел 1).
2. Создать `image2gdram_converter.sln` в корне и `Directory.Build.props` (`Nullable`, `ImplicitUsings`, `TreatWarningsAsErrors`, `Deterministic`, `LangVersion` по умолчанию для .NET 8).
3. Создать проекты по [`architecture.md`](architecture.md): `src/Image2Gdram.Core` (`net8.0`), `tests/Image2Gdram.Reference` (`net8.0`, без ссылки на Core), `tests/Image2Gdram.Core.Tests` (xUnit, `net8.0`); добавить их в решение. `tests/Image2Gdram.App.Tests` создаётся на этапе 6, `tools/TestAssetsGenerator` — на этапе 2.
4. `dotnet build` (0 ошибок, 0 предупреждений) и `dotnet test` — зелёные на пустых проектах.
5. В Core: `MonoBitmap`, `PackingOptions` и перечисления (`PixelFormat`, `PackDirection`, `BitOrder`, `PageTraversal`, `ByteOrder`), `IPacker`, `Mono1bppPacker`, `PackerRegistry`.
6. В Reference: наивная упаковка «по определению» из разделов 3 и 4.3 ТЗ (решения F-01…F-04).
7. Тесты: контрольные байты (F-05), таблица п. 4.2.1, размеры 1536 и 6144 байт, 240 пикселей = 40 байт в 6-битном режиме, спрайт 13×11, все 16 комбинаций на случайных растрах (фиксированный seed), включая 1×1 и 1024×1024; `Locate` против `Pack`; `Unpack(Pack(b)) == b`; биты дополнения и инверсия; сравнение ядра с Reference побайтно.
8. Сверка пресетов с datasheet; результат записать в D-01 [`decisions.md`](decisions.md) (строка «Сверка с datasheet на этапе 1»), вопрос Q-01 оставить открытым до ответа заказчика.
9. Обновить чек-лист, этот файл и [`architecture.md`](architecture.md) (фактическая структура); коммит.
