# Чек-лист требований ТЗ

Файл состояния проекта (раздел 3 `agents.md`). Каждый пункт `specification.md` сопоставлен с местом реализации (модуль из [`architecture.md`](architecture.md) и этап из [`implementation-plan.md`](implementation-plan.md)) и способом проверки. Решения по неоднозначностям — в [`decisions.md`](decisions.md) (ссылки вида D-xx, F-xx, N-xx).

**Состояние на 2026-10-03 (после этапа 1):** реализовано и проверено ядро упаковки: пункты 3.2–3.5, 4.2.1.3, 4.3.1.1–4.3.3.2, 4.3.4.1, 4.3.6.1, 4.3.7.1 (в ядре), 4.6.3, 8.1 и А.8. Частично выполнены 1.1, 3.7, 4.1.2.7, 4.2.1.4, 4.2.1.5, 4.2.2.6, 4.3.4.2, 4.3.7.2, 4.6.1, 4.6.2, 4.6.4, 5.2.3, 6.5, 11.1.1 и 11.1.2: готова часть, относящаяся к этапу 1, а что осталось и на каком этапе — указано в строке. Остальные пункты не реализованы. По мере работы в столбце «Статус» ставится `реализовано` (код есть) и `проверено` (тест зелёный или ручная проверка описана), с указанием теста или записи журнала. Тесты указаны как `Класс.Метод` из `tests/Image2Gdram.Core.Tests`.

Способы проверки:

| Код | Способ |
|---|---|
| UT | модульный тест ядра (`tests/Image2Gdram.Core.Tests`) |
| VT | тест сценария ViewModel (`tests/Image2Gdram.App.Tests`) |
| GT | золотой тест: сравнение сгенерированного текста с образцом |
| RT | побайтное сравнение с эталоном `testdata/reference/` |
| CC | дымовая компиляция `tools/compile-check.ps1` (если есть gcc/clang; на этой машине нет) |
| ПМИ | испытание по `docs/pmi.md` (ручное; часть — силами заказчика) |
| РП | ручная проверка при разработке (результат — в журнале плана) |
| ДОК | проверка наличия и полноты документа |

Модули сокращены: `Core.X` — пространство имён `Image2Gdram.Core.X`; `App` — WPF-приложение `src/image2gdram_converter`.
